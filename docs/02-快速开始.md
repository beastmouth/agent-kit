# 02 · 快速开始

目标：从零到「一句话进去，模型调你的工具，答案出来」，大约 30 分钟。

---

## 1. 加依赖

```xml
<dependency>
    <groupId>com.beastmouth.kit</groupId>
    <artifactId>agent-kit-starter</artifactId>
    <version>0.1.0</version>
</dependency>
```

组件扫描由 starter 的 `AgentKitAutoConfiguration` 完成，**不需要**在你的启动类上加
`scanBasePackages = "com.beastmouth.agentkit"`——加了不会报错，只是同一批 Bean 被扫两次的
无意义开销，还会让人误以为这是必需的。

要长期记忆再加：

```xml
<dependency>
    <groupId>com.beastmouth.kit</groupId>
    <artifactId>agent-kit-memory</artifactId>
    <version>0.1.0</version>
</dependency>
```

### Mapper 扫描（必做，否则一调会话就 NPE）

MyBatis 的 Mapper 不在组件扫描范围里，启动类必须显式列出脚手架的四个 mapper 包：

```java
@SpringBootApplication
@MapperScan({
        "com.beastmouth.agentkit.obs.mapper",
        "com.beastmouth.agentkit.eval.mapper",
        "com.beastmouth.agentkit.memory.mapper",
        "com.beastmouth.agentkit.session.mapper"
})
public class Application {
}
```

症状是：启动正常、DataSource 就绪，第一次调 `AgentSessionStore` 报
`Cannot invoke ... because "this.sessionMapper" is null`。

## 2. 建表

```bash
mysql -uroot -p your_db < agent-kit-starter/src/main/resources/db/agent-kit-schema.sql
```

10 张表，全部是脚手架自有数据，与业务表无外键关系，可按时间清理。

## 3. 最小配置

```yaml
agent-kit:
  provider: deepseek
  base-url: https://api.deepseek.com
  model: deepseek-chat
  api-key: ${DEEPSEEK_API_KEY}

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/your_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: root
    password: ${MYSQL_PASSWORD}
  data:
```

## 4. 写一个工具

工具是 Agent 与业务之间的唯一边界。写 `@Component implements AgentTool`，
或者把同领域的几个动作聚在一个 `ToolGroup` 里（推荐，少写 Bean）。

```java
@Component
public class OrderTools implements ToolGroup {

    private final OrderService orderService;   // 你的 Service，事务/锁/审计照常用

    @Override
    public List<AgentTool> tools() {
        return List.of(new QueryTool());
    }

    private class QueryTool implements AgentTool {
        @Override public String name() { return "order_query"; }

        @Override public String description() {
            return "按订单号查询订单详情。用户给出订单号、问「这单到哪了」时调用";
        }

        @Override public String parametersSchema() {
            return """
                    {"type":"object","properties":{
                      "orderNo":{"type":"string","description":"订单号"}
                    },"required":["orderNo"]}""";
        }

        @Override public ToolOutcome execute(Map<String, Object> args) {
            String no = String.valueOf(args.get("orderNo"));
            Order order = orderService.findByNo(no);
            if (order == null) {
                // 查询 0 条：success=true + rows=0，这是"查了没有"，不是"执行失败"
                return ToolOutcome.ok("没有找到订单 " + no, "[]", 0);
            }
            return ToolOutcome.ok("订单 " + no + " 状态：" + order.status(),
                    Json.toJson(order), 1);
        }
    }
}
```

### `rows` 必须如实填（最容易错的地方）

| 场景 | `rows` | 为什么 |
|---|---|---|
| 查询类，命中 n 条 | `n`（**0 就是 0**） | 「查了但没数据」是幻觉检测最值钱的信号 |
| 写入类（新增/更新/删除） | 影响行数 | 写操作不返回条数，但影响行数有意义 |
| 纯计算 / 打招呼 / 澄清反问 | `null` | 传 0 会被空结果规则误判成「查了没数据」 |

### 失败用 `fail`，不要抛异常

抛异常会被运行器包成一句「执行失败」；`ToolOutcome.fail(msg)` 的 msg 会**原样回灌给模型**，
模型能据此调整措辞（比如提示用户补充参数），而不是笼统报错。

## 5. 写一个子 Agent

```java
@Component
public class OrderAgent implements Agent {

    @Override public String name() { return "order"; }

    @Override public String description() {
        return "订单查询与售后：查订单状态、物流、退换货进度";
    }

    @Override public Set<String> toolNames() {
        return Set.of("order_query");        // 白名单，别的工具模型连名字都看不见
    }

    @Override public String systemPrompt() {
        return """
                你是订单助手。工作口径：
                1. 查订单必须先拿订单号；用户没给就问，不要猜。
                2. 查不到就直说「没有找到该订单」，不要用相似订单顶替。
                3. 退款、改地址这类写操作你做不到，说明清楚并给出替代做法。
                """;
    }
}
```

**提示词里不要写工具清单，也不要写 JSON 输出协议**——运行器会按白名单自动拼接，
手写必然与代码不一致；协议每个 Agent 各写一套会互相打架。只写业务口径：
能做什么、不能做什么、含糊时怎么办。

## 6. 调用

`SubjectScope` 是**示例里的适配类，脚手架不提供**——身份从哪来（JWT？Session？IM 回调？）
只有你的系统知道。照抄 `examples/agent-kit-example/.../support/SubjectScope.java`（把
`set` / `clear` 包成 `AutoCloseable`），或者直接在 `finally` 里调 `RunContext.clear()`。

```java
@Service
@RequiredArgsConstructor
public class ChatUseCase {

    private final ChatEngine chatEngine;
    private final AgentSessionStore sessionStore;
    private final AgentMemoryService memoryService;

    public String chat(String subjectId, Long sessionId, String message) {
        // ① 绑定调用方：决定观测的 subject_id 与工具里的数据隔离范围
        try (var ignored = SubjectScope.open(RunContext.Subject.of(subjectId))) {
            AgentSession session = sessionStore.getRequired(sessionId, "my-app", subjectId);
            // ② 记忆检索：锁外，失败返回空列表
            List<String> memories = memoryService.recall("my-app", subjectId, message);
            // ③ 读历史 → 调模型 → 落库（真实项目要把这一段放进会话锁里）
            List<ChatMessage> history = sessionStore.recentHistory(session.getId(), "my-app", subjectId);
            sessionStore.append(session, "USER", null, message, null);
            AgentResult result = chatEngine.handle(history, message, null, memories, ChatSink.NOOP);
            sessionStore.append(session, "ASSISTANT", result.agentName(), result.reply(), null);
            return result.reply();
        }
    }
}
```

**三条纪律**（漏任何一条都会出安静的错误）：

1. `RunContext` 必须 `try-with-resources` 或 `finally clear()` —— 线程池复用会串号；
2. 会话读写必须在同一个锁里 —— 否则并发请求各读一份历史，库里出现两条互不知情的回答；
3. 调模型前 `RunScope.bindSession(sessionId)` —— 否则 `ai_run.session_id` 为 NULL，
   「按会话看链路」与「点踩倒查 runId」两个功能静默失效。

完整可运行的版本见 `examples/agent-kit-example/.../ConversationFacade.java`，
照抄即可。

```bash
# 示例在 `examples` profile 里，默认构建不含它
mvn -Pexamples clean install -DskipTests
```

## 8. 启动失败对照表

| 报错 | 原因 | 修法 |
|---|---|---|
| `No qualifying bean of type MemoryProperties` | 引了 memory 模块但配置类没注册 | 用 0.1.0 及以上（已修）；自查有没有排掉 `com.beastmouth.agentkit.memory` 包 |
| `required a single bean, but 2 were found`（`ObsProperties`） | `@Component` 与 `@EnableConfigurationProperties` 同时用 | 二选一，见 [01-架构设计 §4.5](01-架构设计.md) |
| `this.sessionMapper is null` | 启动类没 `@MapperScan` 脚手架的四个包 | 见本文 §1 |
| `Table 'ai_run' doesn't exist` | 没执行建表脚本 | 见本文 §2 |
| 模型一直返回兜底话术 | 渠道不通或 `parse_fail` 连续 | 看 `ai_run.error_code` 与 `ai_llm_call` 里的状态；本地 Ollama 注意 `think` 设置 |
