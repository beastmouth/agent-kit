# 07 · 配置参考

+ 数据源。

## `agent-kit.*` —— 模型与运行

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。`false` 时整套组件不装配（代码在、能力关） |
| `engine` | `legacy` | 对话引擎：`legacy`（自研，随 core 自带）/ `agentscope`（需另引 `agent-kit-agentscope`）。值写错或模块缺失会在启动期直接失败并给出依赖片段（匹配忽略大小写，但必须是这两个词）。详见 [08-引擎选型](08-引擎选型.md) |
| `provider` | `ollama` | 首选渠道，对应 `ModelProvider#id()`：内置 `deepseek` / `siliconflow` / `ollama`；此外 `endpoints` 里每个没有内置实现的键会自动长出同名自定义渠道（零代码接任意 OpenAI 兼容网关） |
| `fallback-provider` | 空 | 兜底渠道。首选失败或熔断期内直接走它；空表示不兜底 |
| `failover-cooldown-seconds` | `60` | 首选失败后这段时间内新请求直接走兜底 |
| `base-url` | `http://localhost:11434` | 顶层默认端点（未在 `endpoints` 里单独配的渠道用它） |
| `model` | `qwen3:8b` | 默认模型 |
| `api-key` | 空 | 默认密钥，建议用 `${ENV_VAR}` |
| `temperature` | `0.1` | 采样温度。Agent 场景别调高，工具参数容易发散 |
| `think` | `false` | 是否让模型输出思考过程（支持的渠道才生效；`null` 表示不发该字段） |
| `timeout-seconds` | `300` | 单次模型调用超时。要 ≥ 上游网关超时，否则会白丢还活着的请求 |
| `stream` | `true` | 最终答复是否流式。内网代理缓冲 SSE、网关不认 `stream=true` 时关掉（体验从「首字慢」变成「一次全出」）。按渠道覆盖见 `endpoints.{id}.stream` |
| `stream-usage` | `true` | 流式请求是否索要 usage；不支持的网关会自动去掉该字段重试一次 |
| `intent-provider` | 空 | 意图路由那一步单独用的渠道 id（只接受渠道名，不接受路由键）。空 = 跟随本次请求的路由。这一步每轮必跑、只输出一个 JSON，指到便宜渠道能省一笔 |
| `routes` | 空 | 按业务分渠道，见下节 |
| `max-output-tokens` | `3000` | 单次输出上限。设太小会让思维链吃满正文（表现为空回复 R3） |
| `max-steps` | `4` | 单轮最多几步「决策 → 调工具」，防死循环 |
| `history-limit` | `12` | 每轮带多少条历史进提示词 |
| `prompt-order` | `v1` | `v1` = 记忆在前（旧顺序）；`v2` = 稳定前缀（工具/协议/风格在前，日期与记忆压到最后），第二轮起前缀缓存命中率更高。切换前先跑黄金集对比 |
| `extra-instructions` | 空 | 业务口径追加在系统提示词末尾：术语、单位、行业规范、禁止行为 |
| `context-cache-enabled` | `true` | 会话上下文 Redis 缓存。关掉回退纯 MySQL |
| `context-cache-ttl-seconds` | `1800` | 缓存 TTL |
| `max-sessions-per-owner` | `50` | 每个归属方最多保留的会话数，超出拒绝新建（`SESSION_LIMIT`） |
| `chat-pool-size` | `8` | 对话线程池常驻线程数。按「同时能跑几轮对话」设，不按 CPU 核数 |
| `chat-pool-queue` | `50` | 队列长度。队列满直接拒绝并提示忙，避免无界队列 OOM |
| `chat-pool-keep-alive-seconds` | `60` | 空闲线程存活时间 |

### `agent-kit.endpoints.{id}` —— 按渠道单独配

键名 = `ModelProvider#id()`。**键名撞上内置渠道（`deepseek` / `siliconflow` / `ollama`）是给它填参数；没有内置实现的键会自动注册成自定义 OpenAI 兼容渠道**——想接公司内网网关、one-api、vLLM，配一段端点即可，不用写任何 Java 类，也能进 `routes` 参与业务分流。自定义渠道名随意（`custom`、`company-gateway`…），多个可并存。

| 配置项 | 说明 |
|---|---|
| `base-url` | 该渠道地址（含或不含 `/v1` 取决于渠道实现） |
| `model` | 该渠道默认模型 |
| `api-key` | 该渠道密钥 |
| `think` | 思考开关（`Boolean`，`null` 不发） |
| `thinking` | 部分网关的思考参数（如 `thinking.type`） |
| `reasoning-effort` | 推理强度（`low` / `medium` / `high`，支持的渠道才生效） |
| `stream` | 该渠道是否流式，覆盖顶层 `stream`；`null`/不写 = 跟随全局 |

```yaml
agent-kit:
  provider: deepseek
  fallback-provider: ollama
  endpoints:
    deepseek:
      base-url: https://api.deepseek.com
      model: deepseek-chat
      api-key: ${DEEPSEEK_API_KEY}
    siliconflow:
      base-url: https://api.siliconflow.cn/v1
      model: deepseek-ai/DeepSeek-V3
      api-key: ${SILICONFLOW_API_KEY}
    ollama:
      base-url: http://localhost:11434
      model: qwen3:8b
      think: false
    # 自定义渠道：没有内置实现的键自动生效（OpenAI 兼容协议），可直接被 routes 引用
    custom:
      base-url: https://llm.internal.corp/v1
      model: qwen2.5-72b
      api-key: ${INTERNAL_LLM_KEY}
```

### `agent-kit.routes.{key}` —— 按业务分渠道

键名就是**路由键**，由调用方在 `RunContext.labels` 里传 `model.route`，或由子 Agent 的
`modelRoute()` 声明。解析顺序：**请求标签 > Agent 声明 > 全局默认**（`provider`）。

| 配置项 | 说明 |
|---|---|
| `provider` | 该业务的首选渠道 id。留空 = 沿用全局 `provider` |
| `fallback-provider` | 该业务自己的兜底渠道。**留空就是不兜底**，不继承全局兜底 |
| `description` | 给人看的说明，进日志与健康检查，不参与逻辑 |

```yaml
agent-kit:
  provider: ollama            # 默认：本地，便宜
  fallback-provider: ""       # 默认不兜底；要和上面那条区分开
  intent-provider: ollama     # 意图路由固定用本地小模型

  routes:
    finance:                  # 财务问答：必须用合规模型，不许降级
      provider: deepseek
      description: 财务数据只能走境内合规渠道
    batch:                    # 离线批处理：允许降级，但只降到本地
      provider: siliconflow
      fallback-provider: ollama
```

三条容易踩的约定：

1. **路由内的兜底不继承全局**。跨渠道静默降级会让业务跑到没评估过的模型上，成本、合规、
   数据流向同时失控。要兜底就在该路由里显式写。
2. **路由键写错不报错，只回落默认渠道并 warn 一次**。想确认「到底命中没命中」，打
   `/demo/catalog` 看 `modelRoutes`，或按 `ai_llm_call.provider` 分组看实际落在哪个渠道。
3. **`provider` 只能填已注册的渠道 id**。写错时启动日志会 error 一条带可用清单；
   真跑到请求才暴露的话会返回 `MODEL_UNAVAILABLE`，而不是偷偷换成默认渠道。

同一渠道想开两档模型（如 `deepseek-chat` / `deepseek-reasoner`）不用改脚手架：在 `endpoints` 里配两个键（如 `deepseek-fast` / `deepseek-deep`），各指一档 `model` 即可。要自定义协议（非 OpenAI 兼容）才需要写一个 4 行的 `OpenAiCompatibleProvider` 子类或 `ModelProvider` 实现。

## `agent-kit.router.*` —— 意图路由

| 配置项 | 默认 | 说明 |
|---|---|---|
| `instructions` | 空 | 追加在路由提示词后：划清相近子 Agent 的边界、声明能力边界 |
| `fallback-reply` | 空 | 未委派时的直答话术；空则按已注册 Agent 的描述自动生成 |
| `fallback-keywords.{agent}` | 空 | 模型判「无关」时的关键词兜底。键名必须与 `Agent#name()` 一致 |
| `follow-up-words` | `今天/昨天/上周/这个月/继续…` | 短句追问的省略信号词 |
| `follow-up-max-length` | `10` | 短于这个长度且命中信号词 → 延续上一轮实际处理的子 Agent |

```yaml
agent-kit:
  router:
    instructions: |
      查询与写操作都归 order 助手；它做不到的事交给 feedback 助手如实说明。
    fallback-keywords:
      order: [订单, 下单, 退款, 改地址]
      weather: [天气, 气温, 带伞]
    follow-up-words: [继续, 还有呢, 那]
    follow-up-max-length: 10
```

## `agent-kit.eval.*` —— 评测

| 配置项 | 默认 | 说明 |

## `agent-kit.agentscope.*` —— 仅 `engine=agentscope` 生效（需 agentscope 模块）

| 配置项 | 默认 | 说明 |
|---|---|---|
| `write-claim-guard` | `true` | 模型声称「已完成」但本轮零工具调用 → 自动补一轮强制纠正。关掉只少一道保险 |
| `write-claim-pattern` | 见下 | 「声称已完成」的判定正则。业务口径相关，换业务必须改 |
| `tool-labels` | 空 | `工具名 → 前端状态文案`，没配的用兜底文案 |
| `default-tool-label` | `处理` | 兜底文案，留空则只显示工具名 |

默认 `write-claim-pattern`：

```
已完成|已处理|已提交|已保存|已创建|已新增|已更新|已修改|已删除|操作成功|设置成功|添加成功|提交成功|处理成功|办理成功
```

英文业务可改成 `(?i)(done|completed|submitted|saved|created|updated|deleted)`。
注意它只做关键词命中，真正判定还要叠加「本轮零工具调用」，所以
「已更新了三条记录」这种有工具支撑的回答不会被误抓。

## `agent-kit.context.compaction.*` —— 上下文压缩（两套引擎共用）

设计与验收方法见 [10-上下文压缩接入](10-上下文压缩接入.md)。**默认全关**，不配就与引入前行为完全一致。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 总开关。关掉时压缩器零开销跳过，行为与未引入压缩一致 |
| `trigger-tokens` | `8000` | 估算 token 超过它才压。按 `chars-per-token` 折算，误差只影响「早压/晚压」。实测日常上下文 ~1.25k，所以这是异常回合保险丝（见 [10 §6](10-上下文压缩接入.md)） |
| `trigger-messages` | `0` | 按条数触发；`0` 表示只看 token |
| `keep-messages` | `8` | 压缩后保留的尾部原文条数。太小丢最近语境，太大会让压缩白做 |
| `max-summary-chars` | `1200` | 摘要正文上限。超了说明该提前压，而不是继续往摘要里塞 |
| `provider` | 空 | 生成摘要的渠道 id（`endpoints` 里的键）。留空用默认渠道。**别指向比主模型更慢的渠道**，压缩在主链路上 |
| `chars-per-token` | `1.7` | 字符 → token 折算系数，中文为主取 1.7 |
| `summary-store` | `memory` | `memory`（进程内 LRU，**仅单副本**）/ `redis`（多副本必选，否则同一会话换 Pod 会重生成摘要、前缀缓存失效） |
| `summary-cache-max` | `512` | 内存摘要缓存条数（仅 `memory`） |
| `summary-ttl-seconds` | `604800` | Redis 摘要有效期，7 天（仅 `redis`） |
| `unload-threshold-chars` | `0` | 单条工具结果上限，`0` 不截断。超限保留首尾 + 占位说明 |
| `overflow-retry` | `true` | 模型报 `context_length_exceeded` 时强制压缩后重试一次；需同时开 `enabled` |

```yaml
agent-kit:
  context:
    compaction:
      enabled: true
      trigger-tokens: 8000     # 保险丝，不是日常路径：实测上下文才 ~1.25k（docs/10 §6）
      keep-messages: 8
      provider: deepseek        # 摘要用小模型更省，但别选慢渠道
      summary-store: redis      # 多副本必须
```

> 摘要按「前缀指纹」冻结：同一段前缀永远复用同一份摘要正文，不会每轮重新生成。
> 这是前缀缓存能继续命中的前提，改实现时不要破坏它（见 docs/10 §3）。

## 数据源（不是本脚手架的配置，但必须配）

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/your_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: ${MYSQL_USERNAME}
    password: ${MYSQL_PASSWORD}
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      port: ${REDIS_PORT:6379}
      password: ${REDIS_PASSWORD}
```

Redis 只在用会话缓存/锁时需要；没有 Redis 时 `AgentContextCache` 与 `LockTemplate` 会降级，
但**会话串行化也会一起失效**——生产环境不要省这个。

## 一个完整的生产配置示例

```yaml
agent-kit:
  provider: deepseek
  fallback-provider: ollama
  endpoints:
    deepseek:
      base-url: https://api.deepseek.com
      model: deepseek-chat
      api-key: ${DEEPSEEK_API_KEY}
    ollama:
      base-url: http://localhost:11434
      model: qwen3:8b
  temperature: 0.1
  timeout-seconds: 120
  max-steps: 4
  history-limit: 12
  prompt-order: v2
  extra-instructions: |
    - 金额保留两位小数，单位「元」。
    - 查不到数据就直说，不要估算。

  router:
    fallback-keywords:
      order: [订单, 退款]

  obs:
    trace-io-enabled: false        # 含隐私数据
    detail-retention-days: 30

  eval:
    sample-rate: 0.05
    judge-enabled: true
    judge-provider: deepseek
    judge-model: deepseek-chat
    golden-enabled: false

  memory:
    enabled: true
    collection: myapp_memory       # 改过名
    top-k: 5
    max-per-owner: 200
```
